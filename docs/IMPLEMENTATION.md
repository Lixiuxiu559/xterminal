# 实施计划与验收

日期：2026-10-22\
依据：[系统架构](ARCHITECTURE.md) · [协议](architecture/PROTOCOL.md) · [设计规范](DESIGN.md)

目标是按可运行的纵向链路交付。先做真实 Shell 和本机生命周期，再接 Agent，最后开放经过授权的手机入口。没有真实连通之前，不把原型里的模拟结果带入完成统计。

当前进度（0.1.1）：三引擎桌面工作空间、HTTPS/WSS 局域网接入与单端控制已实现。Agent 桌面四阶段协议端到端、两引擎真实对话/工具/重启续聊，以及 Host/应用强杀后的进程回收与历史恢复已通过本轮验收。试用包已生成；手机证书信任/软键盘真机、长期压力、独立安装与签名公证仍待验收。具体代码边界和证据见 [开发进度](PROGRESS.md)，下面保留各里程碑的目标，不将计划清单直接视为全部完成。

## M0：工程基础与风险验证

交付：pnpm workspace、Electron 主进程与安全 preload、Host 入口、React 应用、领域协议、数据库初版、假引擎测试夹具。

优先验证：

- 打包后的 utility process 同时加载 node-pty 和 SQLite。
- 关窗后测试进程仍在，托盘可恢复窗口；退出后清理自己创建的测试进程。
- Claude：所选 SDK / CLI / 认证组合、流式回复、权限与提问、停止、明确 ID 恢复。
- Codex：按本机 schema 完成初始化、权限 request/response、turn 事件和恢复。
- 手机本地 TLS 证书信任流程，分别记录 iOS Safari 与 Android Chrome 的真实步骤。

验收：记录可重复执行的 smoke 脚本和版本矩阵。未通过的组合标注 unavailable，不能改用自动批准、明文网络或隐藏认证问题绕过。

工程、协议、状态机与数据库约束已落地；M0 的手机证书信任与兼容矩阵继续按未完成项跟踪。

## M1：桌面真实 Shell 纵向链路

范围：桌面批准项目目录 → 创建固定 Shell 会话 → PTY 输出 → xterm 渲染 → 输入 / Ctrl+C / resize → 切换会话。

验收：

- `pwd`、环境、`cd` 在同一 PTY 内保持；不是每条命令重新 spawn。
- 服务持续输出时仍能及时中断，UI 和 Host 内存有上限。
- 关闭/重新打开窗口仍连接原进程；显式结束后状态准确。
- 只允许控制端 resize，快照与实时输出没有重复。

## M2：项目、历史与恢复

范围：SQLite 仓储、事务事件、列表/历史投影、命令回执、单会话控制权与项目 Agent 锁。

验收：

- 重启后项目和会话可见，引擎字段不能修改。
- 重复 commandId 不重复执行；不同 payload 复用 ID 被拒绝。
- 快照 / 实时订阅竞态不丢事件，最终回复不重复追加。
- 崩溃后活跃轮次标为 interrupted / outcome_unknown，不自动重发任务。
- 已结束 Shell 不伪装仍在运行，用户可明确创建新运行实例。

## M3：Codex 与 Claude Code

先按 M0 结果完成风险较小的适配器，再接另一个；原型页面迁移为真实组件。

验收：

- 两种引擎分别完成一次真实开发请求、工具事件、权限、问题、停止和恢复。
- 同目录两个 Agent 不同时执行写轮次；不同项目可独立执行。
- 未支持的工具或交互不自动批准，前端有明确原因。
- 引擎崩溃只结束对应运行实例；不会将回复正文当作完成通知。
- 外部认证流程在本机进行，手机与日志不出现密钥或 token。

## M4：手机内网接入

范围：默认关闭的 LAN 服务、HTTPS/WSS、设备配对、桌面确认、设备撤销、共享会话、单端控制、重连。

验收：

- iOS / Android 真机完成证书信任和首次配对。
- 未配对、过期、撤销设备不能读历史、订阅输出或输入。
- Origin/Host 不匹配、越权目录与超限消息被拒绝。
- 断线时电脑任务继续；Agent 补事件、PTY 补快照；Shell 输入不自动重发。
- 两端同时接管时只有一个成功有效 generation，旧端后到输入被拒绝。
- 手机调整终端宽度不会与桌面观察端反复抢尺寸。

## M5：可用性与首发包装

范围：设计系统迁移、空状态/错误/等待态、目录与引擎检测引导、生命周期、内存/输出压测、macOS 安装包。

验收：

- 320 / 390 / 768 / 1440px 及真实软键盘操作不遮挡关键动作。
- 显示已安装引擎版本、是否可用、恢复失败的具体原因。
- 原生模块签名、资源 unpack、子进程路径在安装包内通过测试。
- 无运行时 CDN；生产包不带开发端口或测试自动批准配置。

代码签名和公证若需要用户的开发者身份，先完成可本地检查的构建，再处理签名配置；不凭空声称可公开分发。

## 测试设计

| 层 | 必测场景 | 验证方式 |
| --- | --- | --- |
| 领域 | 引擎固定、状态转换、过期控制权、重复授权、同项目冲突 | 无真实引擎的确定性单元测试 |
| 存储 | 事务原子性、FK、不可变触发器、命令唯一键、迁移失败 | 临时 SQLite 集成测试 |
| 引擎 | 分片 JSON、乱序结束、未知事件、审批、停止、异常退出 | 官方 schema + 已脱敏夹具 + 本机 opt-in smoke |
| 多端 | 断线、快照订阅竞态、撤销、控制权冲突 | Host + 两个客户端集成测试 |
| 终端 | 高速输出、Unicode、resize、快照屏障、Ctrl+C | 受控 PTY 进程与 xterm 状态比较 |
| 安全边界 | 非法 Origin/Host、未配对访问、远端目录注入、XSS | 自动化负向用例 |
| UI | 主题、导航、授权、输入、手机布局 | 浏览器 E2E + 真机验证 |

默认测试不调用真实模型、不修改用户项目、不读取用户凭据。真实引擎 smoke 使用专用临时项目，可能产生模型费用或文件修改，实际运行时需明确目标与范围。

## 工程执行约定

- 第一次安装固定兼容版本并提交 lockfile，升级引擎后更新 schema 和夹具。
- 领域/协议不导入 Electron、React 或具体 SDK，保证可以独立运行测试。
- 每个里程碑完成后再声明对应能力可用；原型、基础契约、打包验证和产品功能分别统计。
- 不先实现云端、远程穿透、插件市场或完整 IDE。
