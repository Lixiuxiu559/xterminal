# 产品需求文档

版本：v0.4\
更新日期：2026-10-22\
阶段：桌面三引擎与内网连接已实现，继续进行产品集成与真机验收\
项目代号：XTerminal（正式产品名待定）

交互与视觉规范见 [设计规范](DESIGN.md)，可运行原型见 [原型说明](../prototype/README.md)。系统边界与开工默认值见 [系统架构](ARCHITECTURE.md)。

## 1. 背景与目标

用户目前通过 Ghostty、iTerm2、Warp 使用 Claude Code 和 Codex 开发。现有使用体验存在两个主要问题：

1. 项目、标签和多个开发会话不好管理，切换时不容易找到目标上下文。
2. 离开电脑后，缺少方便的手机入口，无法继续查看和操作电脑上正在进行的开发会话。

本产品提供一个桌面应用，将电脑本地的 Claude Code、Codex 和 Shell 会话集中管理，并允许手机通过内网连接地址访问同一个会话。Agent 会话以对话为主要交互方式；Shell 会话用于直接运行命令，不要求使用 Agent。

第一版优先验证完整体验：在电脑创建会话并开始任务，在手机浏览器打开内网地址，查看进展并继续交互。

## 2. 已确认的产品边界

以下内容已在需求讨论中明确，后续设计和实现以此为约束。

| 项目 | 边界 |
| --- | --- |
| 产品形态 | 桌面应用，提供手机访问页面 |
| 主要交互 | Claude Code、Codex 使用类似 ChatGPT 的对话界面；Shell 使用终端交互 |
| 执行引擎 | Claude Code、Codex、Shell |
| 引擎选择 | 创建会话时选择；打开已有会话时沿用原选择 |
| 引擎切换 | 会话创建后不允许切换，包括运行中、空闲时以及重新打开后 |
| 引擎适配 | 允许针对不同引擎提供专属页面与功能交互 |
| 执行位置 | 任务在电脑本地执行 |
| 手机接入 | 通过连接地址访问电脑端，第一版仅支持内网 |
| 连接方式 | 手机直接连接电脑，不通过中继服务转发会话数据 |
| 电脑唤醒 | 不提供保持唤醒或远程唤醒 |
| 云端执行 | 不提供 |
| 产品名称 | XTerminal 暂作项目代号，正式名称待定 |

“本地执行”指引擎进程、命令和文件操作发生在电脑上，并不意味着模型推理离线。Claude Code、Codex 自身需要的模型服务连接，按所选引擎的配置工作。

## 3. 目标用户与核心场景

第一阶段主要服务于使用 Claude Code、Codex 或直接执行 Shell 命令，需要管理多个本地开发会话的个人开发者。

### 场景 A：电脑上开始开发

用户选择本地项目目录，创建会话，选择 Claude Code 或 Codex，然后通过对话提出开发需求。页面持续展示回复和执行状态，并在需要用户输入或授权时提供操作入口。

### 场景 B：管理多个会话

用户在不同项目、不同任务之间切换。会话列表应帮助用户识别会话所属项目、所用引擎及当前状态，减少对大量终端标签的依赖。

### 场景 C：手机继续操作

电脑保持开机且会话服务可用。手机与电脑网络互通，用户打开电脑提供的内网地址，完成访问授权后，进入已有会话查看输出、发送消息或处理交互请求。执行仍发生在电脑上。

### 场景 D：手机断线后重新连接

手机网络断开或页面关闭，不应主动终止电脑上的任务。重新连接后，应能恢复查看当前会话及其最新状态。

### 场景 E：直接运行 Shell 命令

用户创建会话时选择 Shell，在电脑本地运行命令、启动开发服务、查看日志或执行脚本，无需启动 Claude Code 或 Codex。手机可以连接同一个 Shell 会话，查看输出并输入命令。

## 4. 第一版建议功能范围

本节是根据已确认边界整理的 MVP 草案。尚未逐项确认的交互细节列在第 10 节。

### 4.1 项目与工作目录

- 可以选择电脑本地目录作为会话工作目录。
- 按项目组织会话，同一个项目可以创建多个会话。
- 手机访问已有项目和会话时，使用电脑上的工作目录。
- 不将电脑文件复制到手机后执行任务。

### 4.2 会话创建与管理

建议创建流程：选择项目或工作目录 → 选择 Claude Code、Codex 或 Shell → 创建会话 → 进入对应的对话或终端页面。

- 每个会话绑定一个不可切换的引擎和一个初始工作目录；Shell 会话中可以使用 `cd` 等命令改变当前目录，不改变会话所属项目。
- 会话列表展示标题、引擎标识和当前状态。
- 支持创建、切换和重命名会话。
- 进入已有会话时恢复其内容和状态，不重新选择引擎。
- 电脑与手机访问的是同一个会话，不因设备切换自动创建副本。
- 引擎不可用时提示原因和处理入口，不自动切换为另一个引擎。

### 4.3 Agent 对话与执行反馈

本节适用于 Claude Code 和 Codex；Shell 的交互要求见第 4.8 节。

- 支持输入消息并发送给当前会话的引擎。
- 持续展示引擎回复，执行期间有明确的状态反馈。
- 展示必要的工具调用、命令执行结果和错误信息；长输出可折叠查看。
- 支持请求停止当前任务，并展示实际停止结果。
- 引擎要求权限确认或补充信息时，在页面内提供对应交互。
- 不将“已发送停止请求”直接显示为“任务已停止”。

### 4.4 不同引擎的页面适配

项目导航、会话列表可以共用；Agent 的基础消息展示可以共用。Shell 提供终端视图，引擎配置、执行事件、权限请求和特殊能力按引擎分别适配。

- 页面持续显示当前会话使用的引擎。
- 不要求三种引擎具备完全一致的功能，也不要求 Shell 命令呈现为 AI 对话。
- 仅展示当前引擎及当前接入方式实际支持的能力。
- 特殊交互的具体范围，需在引擎接入验证后确定。
- 不通过解析终端屏幕文字作为对话和权限交互的唯一依据；具体接入方式留待技术验证。

### 4.5 手机内网接入

- 电脑端提供手机可访问的内网连接地址。
- 手机通过浏览器使用适配小屏幕的页面，无需安装手机应用。
- 手机端可以查看会话；Agent 会话支持发送消息、请求停止任务和处理受支持的交互请求；Shell 会话支持终端输入、查看输出和发送 Ctrl+C 等必要控制操作。
- 连接失败或断线时清楚提示连接状态，避免把尚未送达的消息显示为已发送。
- 手机断线不主动终止电脑上的会话。
- 第一版不承诺跨公网、跨隔离网络或任意 Wi-Fi 环境的连接能力。
- 二维码作为简化打开地址的建议入口，具体是否纳入第一版待确认。

### 4.6 访问授权

连接地址涉及对电脑开发环境的操作权限，建议第一版包含基本的访问控制。

- 手机访问需要得到电脑端授权，不能仅凭发现地址直接操作。
- 电脑端可以关闭手机访问，并撤销已有访问授权。
- 不在手机页面暴露引擎的认证凭据。
- 授权方式、有效期和关闭访问后的连接处理方式待设计。

### 4.7 历史记录与运行生命周期

- Agent 对话历史保存在电脑本地；Shell 输出历史的保存范围和保留策略待确定。
- 手机重连后可以获取历史内容和当前执行状态。
- 切换会话或手机断线不代表结束任务。
- 电脑休眠、关机或会话服务退出时，手机无法继续操作。
- 历史记录恢复和任务进程恢复分别处理；本地存在历史记录不代表任务还在运行。
- 架构默认关闭桌面窗口保留后台会话，显式退出结束服务；不提供独立于应用的系统 daemon。实现与验证状态见 [开发进度](PROGRESS.md)。

### 4.8 Shell 终端交互

- Shell 是第一版正式支持的第三种会话引擎，创建后同样不允许切换为其他引擎。
- 直接运行电脑上的 Shell，不依赖 Agent 安装、登录或模型服务。
- 提供命令输入、持续输出和基本交互操作，支持连续执行多条命令。
- 同一个运行中的 Shell 会话保留当前目录和环境等进程上下文，不将每次输入视为一个全新会话。
- 支持长时间运行的命令及持续输出，例如开发服务和日志查看。
- 提供回车、Ctrl+C 等必要控制操作；中断当前命令不等于关闭整个 Shell 会话。
- 电脑和手机连接同一个 Shell 会话，手机断线不主动结束 Shell 及其中运行的命令。
- Shell 不提供 Agent 式自然语言理解、工具调用卡片或模型权限确认；手机访问仍遵循统一的访问授权机制。
- 默认 Shell、是否允许选择 Shell 程序，以及全屏终端程序的兼容范围待确定。

## 5. 建议信息结构

桌面端：项目导航 → 会话列表 → 按引擎展示对话或终端主区域。

对话区域包含会话标题、引擎标识、执行状态、消息内容、执行详情及输入区。引擎特殊交互在需要时出现。

Shell 区域包含会话标题、引擎标识、连接及进程状态、终端输出和输入操作。

手机端：项目与会话入口 → 单会话对话或终端页面。优先保证 Agent 的阅读、输入、停止和权限确认，以及 Shell 的输出查看、命令输入和中断操作可用，具体布局不必与桌面完全一致。

## 6. 建议会话状态

下表主要用于 Agent 会话。Shell 会话至少区分进程运行、已退出和异常；命令级状态能否可靠识别留待技术验证，不套用 Agent 的“等待用户”等状态。

| 状态 | 用户可理解的含义 |
| --- | --- |
| 就绪 | 当前没有任务执行，可以发送消息 |
| 执行中 | 引擎正在处理请求 |
| 等待用户 | 引擎需要授权、回答问题或其他输入 |
| 正在停止 | 已请求停止，等待引擎确认 |
| 异常 | 当前执行或引擎连接出现问题，需要处理 |

设备连接状态与会话执行状态分开显示。例如，手机显示“连接已断开”时，不据此判断电脑任务已经停止。

## 7. 第一版明确不做

- 保持电脑唤醒、远程唤醒，以及电脑关机或休眠后的持续执行。
- 云端运行开发任务、云端托管会话和云端保存对话历史。
- 公网穿透、中继转发及外网访问兜底。
- 同一会话中途切换 Claude Code、Codex 或 Shell 引擎。
- 自动把一种引擎的上下文迁移到另一种引擎。
- 多个 AI 引擎在同一会话内协同执行。

## 8. 待评估的扩展功能

以下内容曾作为产品建议提出，尚未确定纳入第一版，不能直接视为开发范围：

- Agent 会话内额外提供原始终端输出入口（独立 Shell 会话已纳入第一版）。
- 文件浏览和代码改动 diff 查看。
- 会话收藏、归档和删除（搜索已纳入首版设计）。
- 任务完成或等待授权的通知。
- 手机创建新项目、选择电脑目录。
- 多手机接入和并发操作。

## 9. 第一版验收场景草案

1. 在电脑上选择项目，分别创建 Claude Code 和 Codex 会话，两者均能完成基础对话与实际开发任务。
2. 会话创建后，电脑与手机均无法将其切换为另一引擎；重新打开也保持原绑定。
3. 同一项目下的多个会话可以切换，消息内容和引擎绑定不混淆。
4. 手机在网络互通的内网环境中，通过电脑提供的地址和授权进入已有会话。
5. 手机能够查看持续更新的输出并发送后续消息，电脑能看到同一会话的变化。
6. 对已接入支持的权限请求，用户可以在页面内处理，引擎能收到对应结果。
7. 手机断线期间电脑任务继续；重连后可以看到最新内容，避免重复提交同一条消息。
8. 请求停止后，页面能区分正在停止、已停止及停止失败等结果。
9. 撤销手机访问授权后，该手机不能继续读取会话或提交操作。
10. 电脑不可达时，手机显示连接失败或断线，不显示虚假的任务执行结果。
11. 不启动 Agent 即可创建 Shell 会话，连续运行命令并保持当前目录等上下文。
12. 在 Shell 会话中启动持续输出的命令，手机可以查看输出、继续输入并发送 Ctrl+C；命令中断后仍可使用该 Shell。
13. 手机断线后 Shell 命令继续运行，重新连接时接入原会话，不重新启动命令或 Shell。
